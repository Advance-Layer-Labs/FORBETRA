# Forbetra Full QA Reassessment - 2026-10-26

Rerun of the exhaustive persona-by-scenario QA (same method as the 2026-03-14 full assessment and reassessment) against `main` at 958913e, which includes Kieran's PR #26 (domain rebuild and rename), PR #27 (coach onboarding and invites) and PR #28 (October 14 tester-readiness fixes).

Two layers this time:

1. **Code-based synthetic QA.** Five parallel agents walked every persona x scenario in the UX evaluation framework (docs/ux-evaluation-framework.md) through the actual code paths: individual, coach, reviewer, admin/cross-role, API/jobs/backend. Every issue cites a file:line that was read.
2. **Live browser walkthrough.** Headless Chromium against a local dev server pointed at the production database, with throwaway Clerk test accounts (qa-live-coach, qa-live-ind-a, qa-live-ind-b, one reviewer). Email and SMS in mock mode. Screenshots in `screenshots/qa5_01` through `qa5_27`. Test rows were deleted afterwards.

Static baseline: `npm run check` 0 errors / 3 warnings, `npm test` 132/132, `npm run lint` clean on code (only the October QA markdown files fail prettier).

**Production could not be probed from this network.** The AT&T Wi-Fi captive portal on Marc's connection intercepts TLS to Vercel's 76.76.21.x range and serves a `secure-login.attwifi.com` certificate for app.forbetra.com, so the Clerk-key and Sentry checks from October 14 remain unverified (see section 7). This is a local network artifact, not a Forbetra defect.

Auth and access (good): every `/api` route is behind `requireRole`/`requireAuth`, cron bearer auth, Svix, or Twilio signature. Coach endpoints verify `CoachClient`; individual endpoints scope by `dbUser.id`; insight feedback checks ownership. Impersonation requires an ADMIN Clerk session and is excluded on `/admin` and `/api/admin`. Debug endpoints are hard-off in production. CSRF: SvelteKit's origin check is replaced by an equivalent custom hook that only exempts the Twilio path.

Input validation (fine, with gaps): Zod schemas cover check-in, reviewer feedback, onboarding and new journey (`lib/validation/*`). Gaps: settings fields (#15), reviewer email (#21), `ask` message shape (#17), several unguarded `request.json()` calls (#31).

Data integrity (good): cascade/SetNull rules are complete; unique constraints on Feedback and Insight hold the invariants the domain layer relies on. Hot queries are indexed (`Journey.status`, `Insight.[type,status]`, `Token.[reviewerId]`, `CoachInvite.[email]`, `NotificationCap.[key,createdAt]`). Remaining risk is #5 (unique index + FAILED rows) and #7's non-transactional journey rollover.

Notifications (mixed): email failover works; SMS templates are TCPA-footed; timezone and notification-hour gating works. The reminder scheduling logic is where the real defects are (#1, #8, #9) and third-party opt-out is absent (#2, #12). The `baseUrl` double-scheme (#11) depends on how `PUBLIC_APP_URL` is set in Vercel - check it before testers go out.

Cron/serverless (weak): sequential AI loops with no `maxDuration` (#3); week-boundary mismatch makes the Sunday synthesis wrong for most users (#4); FAILED insights are sticky (#5, #6). Rate limiting is only real if Upstash is configured (#20).

AI (acceptable): model id is overridable; prompt caching on the big system prompt; failures are recorded with status/metadata; `suggestFocusAreas` degrades to `[]`. PII sent to the model: individual name (email as fallback in coach prep), reviewer names, raw check-in notes, reviewer comments/observations, coach notes. No emails/phones except the coach-prep name fallback (`generateInsight.ts:688`). Reasonable for the product; worth a line in the privacy policy.

Clerk coupling (weak): per-request `getUser` (#10). Webhook only handles `user.deleted` and swallows failures (#19).

#### 6. Strengths

1. Cascade strategy is complete and matches the migration; the Clerk delete webhook and admin delete can no longer fail on FK constraints.
2. Token hygiene: 256-bit random, SHA-256 at rest, single-use, expiry-after-submitted ordering, reissue expires old links, constant-time cron secret compare.
3. Email layer: real two-way provider failover with mock mode, consistent `escapeHtml`, CAN-SPAM address in every footer.
4. Domain feedback invariants enforced twice (app + DB unique) with a typed `DuplicateFeedbackError` that the token page turns into a friendly "already submitted" state.
5. Insight lifecycle is observable: PENDING -> GENERATING -> COMPLETED/FAILED with error metadata, prompt hash and model id recorded; cron handlers return counters.
6. Reminder time gating is timezone-correct and the overdue cap survives without Redis via `NotificationCap`.
